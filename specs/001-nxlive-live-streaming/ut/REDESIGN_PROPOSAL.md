## F-001 개선안: 하이드레이션 창 초기 인터랙션 무시

**문제 요약**: 로드 직후 수백 ms 동안 클릭/입력이 조용히 무시되고, 진행 상태 표시가 없다.

### 안 A — 최소 변경
- 라이브 시청 페이지에 `app/live/[channelId]/loading.tsx` 스켈레톤 추가.
- 주요 버튼(팔로우·전송)은 hydration 전까지 시각적으로 동일하되, 클릭 시 무반응 방지를 위해 서버 컴포넌트 영역 축소.
- 변경 범위: `loading.tsx` 1~2개 추가.
- 예상 효과: 진입 시 "로딩 중" 인지 → 조기 클릭 감소.
- 트레이드오프: 하이드레이션 창 자체는 남음(초고속 클릭은 여전히 가능).

### 안 B — 인터랙션 준비 상태 게이트 (권장)
- `useHydrated()` 훅(마운트 후 true)으로 팔로우·전송·필터 버튼을 hydration 전 `aria-disabled`+시각적 비활성 처리 → 준비되면 활성.
- 홈 필터/검색에 입력 반영 로딩 마이크로 인디케이터.
- 변경 범위: 훅 1개 + 인터랙티브 컴포넌트 3~4개.
- 예상 효과: 조기 클릭이 "비활성"으로 보여 사용자가 대기 인지 → N1 충족.
- 트레이드오프: 약간의 구현 비용, 버튼 깜빡임 최소화 필요.

**권장**: 안 B — P2 초고속 사용자의 무반응 경험을 근본 차단.

## F-002 개선안: 팔로잉 뷰 부재

**문제 요약**: 팔로우는 되나 다시 찾을 화면이 없어 P2 리텐션 동선 단절.

### 안 A — 최소 변경
- 헤더 내비에 "팔로잉" 링크 + `/following` 페이지(팔로우 채널 목록, localStorage 기반).
- 변경 범위: 페이지 1개 + 헤더 1줄.
- 예상 효과: 재방문 동선 확보.

### 안 B — 홈 통합 (권장)
- 홈 최상단에 "팔로잉" 레일(팔로우 채널의 현재 라이브 우선) + `/following` 전체 보기.
- 변경 범위: 홈 섹션 1개 + 페이지 1개.
- 예상 효과: JOURNEY 5단계(재방문) 핵심 충족 — P2 리텐션 직접 개선.
- 트레이드오프: 홈 레이아웃 조정.

**권장**: 안 B — 단, **spec MVP 범위 밖** → 다음 이터레이션(또는 Phase 2)에서 spec 갱신 후 진행.
