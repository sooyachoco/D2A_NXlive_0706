# NXlive — 게임 라이브 스트리밍 (MVP)

> 이 문서는 NXlive MVP의 전체 범위와 요구사항을 정의합니다.
> 디자인 방향: `design/design-direction.md` (C — NX Basic 1.0v 다크+라이트) · 데이터: 전부 Mock

## 개요

NXlive는 넥슨 게임 유저(외부 회원)가 게임 라이브 방송을 발견하고 시청하는 웹 스트리밍 플랫폼이다.
MVP는 **라이브 발견 → 라이브 시청**의 핵심 여정을 중심으로, 채널·클립·검색을 포함한 5개 페이지를 다룬다.
이번 빌드는 백엔드 없이 **Mock 서비스 레이어 + 더미 데이터**로 전체 UI를 검증한다 (영상은 플레이스홀더/샘플 처리).

- **메인 기능 ★**: 라이브 시청 페이지 (비디오 플레이어 + 실시간 채팅 + 시청자 카운트) — 가장 복잡하고 실시간성이 핵심
- **대상 사용자**: 외부 유저 (넥슨 회원) · 인증 없음(none)
- **디자인 시스템**: NX Basic 1.0v (`DESIGN_SYSTEM=nxbasic`)
- **유사 제품**: Twitch · 치지직(CHZZK) · SOOP

## 사용자 시나리오

### 시나리오 1: 라이브 발견 → 시청 (핵심 여정)

**사용자**: 넥슨 게임을 즐기는 외부 유저
**목적**: 지금 방송 중인 게임 라이브를 찾아 바로 시청
**흐름**:
1. 홈에 진입하면 지금 방송 중인 라이브가 카드/랭킹으로 노출된다
2. 관심 게임(예: 메이플스토리) 카테고리로 필터링하거나 랭킹에서 고른다
3. 라이브 카드를 클릭하면 라이브 시청 페이지로 이동한다
4. 플레이어로 방송을 보며 실시간 채팅에 참여하고, 현재 시청자 수를 확인한다
5. 마음에 드는 스트리머를 팔로우한다

### 시나리오 2: 채널 탐색

**사용자**: 특정 스트리머의 팬
**목적**: 스트리머의 현재 방송·지난 클립 확인
**흐름**:
1. 라이브 시청 페이지 또는 검색에서 채널명을 클릭한다
2. 채널 페이지에서 방송 상태(라이브/오프라인)·팔로워·소개를 본다
3. 지난 클립 목록을 스크롤하며 하이라이트를 재생한다

### 시나리오 3: 검색

**사용자**: 특정 게임/스트리머/키워드를 찾는 유저
**목적**: 원하는 라이브·채널·클립을 빠르게 탐색
**흐름**:
1. 검색창에 키워드를 입력한다
2. 라이브 / 채널 / 클립 탭으로 결과를 구분해 본다
3. 결과 항목을 클릭해 시청/채널 페이지로 이동한다

## 기능 요구사항

### 페이지 목록 (MVP 5종 — Step 2.7 프로토타입 기준)

| 페이지 | 경로 | 대응 기능 | 비고 |
|---|---|---|---|
| 홈 (라이브 발견) | `/` | F-01, F-02 | 샘플 C 레이아웃 기반 (다크 상단 + 라이트 카드) |
| **라이브 시청 ★** | `/live/:channelId` | F-03, F-04, F-05 | 메인 기능 — 플레이어+채팅+카운트 |
| 채널 | `/channel/:channelId` | F-06, F-07 | 스트리머 프로필·클립 |
| 클립 | `/clips` | F-07 | 하이라이트 피드 |
| 검색 | `/search` | F-08 | 라이브/채널/클립 통합 |

### 기능별 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F-01 | 홈에서 "지금 라이브" 목록을 카드 그리드로 노출한다 (게임·스트리머·시청자 수·LIVE 뱃지) | 필수 |
| F-02 | 홈에서 실시간 인기 랭킹과 카테고리(게임별) 필터를 제공한다 | 필수 |
| F-03 | 라이브 시청 페이지에서 비디오 플레이어를 표시한다 (Mock: 플레이스홀더/샘플) | 필수 |
| F-04 | 라이브 시청 중 실시간 채팅을 표시·전송한다 (Mock: 로컬 상태 + 자동 유입 시뮬레이션) | 필수 |
| F-05 | 라이브 시청 페이지에 현재 시청자 수·채널 정보·팔로우 버튼을 표시한다 | 필수 |
| F-06 | 채널 페이지에서 방송 상태·팔로워·소개를 표시한다 | 필수 |
| F-07 | 채널/클립 페이지에서 지난 클립을 카드로 나열하고 재생 진입한다 | 필수 |
| F-08 | 검색에서 키워드로 라이브/채널/클립을 탭 구분하여 조회한다 | 필수 |
| F-09 | 스트리머 팔로우/언팔로우 상태를 로컬(Mock)로 관리한다 | 선택 |
| F-10 | 반응형 레이아웃 (데스크톱 우선, 태블릿까지 대응) | 선택 |

## 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 인증 | 없음 (none) — 공개 열람. 팔로우 등은 로컬 상태로 시뮬레이션 |
| 디자인 | NX Basic 1.0v 토큰 준수 (다크: bc-1000/db·pc-500 / 라이트: lb-200·pc-800). 임의 변주 금지 |
| 접근성 | WCAG AA 텍스트 대비 4.5:1 이상, 키보드 포커스 가시 |
| 반응형 | 1440px 콘텐츠 기준, ~768px 태블릿 대응 |
| 데이터 | 전부 Mock 서비스 레이어 (`NEXT_PUBLIC_USE_MOCK=true`) — Phase 1에서 실제 API로 교체 가능 구조 |
| 성능 | 초기 로드 LCP < 2.5s (프로토타입 기준, 목표치) |

## 제약사항

- **영상 송출/재생 인프라는 범위 밖**: 플레이어는 플레이스홀더 또는 공개 샘플로 대체. 실제 HLS/CDN 연동은 후속 integration.
- **백엔드 없음**: 모든 데이터는 Mock. 서비스 레이어를 Mock↔API 전환 가능한 구조로 작성.
- **실시간(WebSocket) 미연동**: 채팅·시청자 수는 클라이언트 타이머로 유입을 시뮬레이션. 실제 WebSocket은 백엔드 결정 후.
- **인증 없음**: 로그인/개인화는 이번 범위 밖. 팔로우는 로컬 상태.

| (후속) 실시간 채팅·시청자 수 | 🔴 외부 연동 | WebSocket 서버 — 백엔드 결정 후 |

> 🔴 외부 연동은 이번 MVP 범위 밖이므로 `analyze-integrations`는 후속 단계에서 실행한다.

## 용어 정의

| 용어 | 정의 |
|---|---|
| 라이브(Live) | 현재 방송 중인 스트림 |
| 채널(Channel) | 스트리머의 방송 공간 |
| 클립(Clip) | 방송 중 하이라이트 짧은 영상 (VOD) |
| 시청자 수 | 특정 라이브를 현재 보고 있는 동시 사용자 수 |
| Mock | 백엔드 없이 프론트에서 더미 데이터로 동작시키는 서비스 레이어 |
